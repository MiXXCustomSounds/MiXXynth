# MiXXynth — Presets and the randomizer (M7)

What a patch IS, how the bank is laid out, and what a roll guarantees. The decisions behind
these are in `docs/PLAN-M7.md`; this is the reference.

## The patch

A patch is a state tree, and the tree is JUCE's own shape: one `<PARAM id="..." value="..."/>`
child per parameter, plus a `shapes` child for the modulation modules and an `fxFiles` child
when a slot holds an impulse response.

```xml
<MiXXynthState>
  <PARAM id="fmIndex" value="0.42"/>
  <PARAM id="op1ratio" value="1.0"/>
  ...
  <shapes numLfos="1" numEnvs="1">...</shapes>
</MiXXynthState>
```

That is exactly what a DAW stores when it saves the plugin, so a state exported from a session
loads as a preset and the other way round. The three names (`PARAM`, `id`, `value`) are
`AudioProcessorValueTreeState`'s `valueType`, `idPropertyID` and `valuePropertyID`; they are
private there, so they are spelled out in `PresetStore.h`.

**A value written as a property of the ROOT is silently ignored on load.** The first version of
this bank was written that way: thirty presets parsed, listed, loaded, and produced one init
patch. `MiXXynthPatchAudit` now loads every preset in the bank and compares the result, so the
mistake fails a test instead of sounding wrong.

## A preset is partial

A preset file carries only what it CHANGES. Loading one is:

1. take the init tree (`buildInitState` - every parameter at its default, the default
   modulation modules, an empty rack),
2. overlay the preset's parameter nodes **by id**,
3. apply the result once.

The consequence, stated plainly because it is a real trade: **a parameter a preset does not
mention comes back at its DEFAULT, not at the previous patch's value.** That is what makes a
load deterministic, and it is why changing a parameter's default changes every preset that did
not mention it.

The alternative - writing all 459 parameters into every file - would make a factory preset 460
lines instead of 40, and the bank unreviewable. `diffState` produces the same format when you
save, so a user preset and a factory preset are the same shape.

## The bank

| | where |
|---|---|
| Factory | `presets/<Category> - <Name>.xml` in the repo, embedded in the binary |
| User | `%APPDATA%/MiXXynth/Presets/<Category> - <Name>.xml` |

Both appear in one list, grouped by category, factory items marked. A factory preset cannot be
overwritten or deleted: the bank lives in the binary, so an overwrite would be a lie. A user
preset can be overwritten, which is what SAVE is for.

The name carries the category - `Bass - Sub Growl` - so the category travels with the file when
it is copied or moved, and there is nothing inside the file to fall out of step with its name.
A file with no ` - ` in it lands in `Other` rather than being rejected.

The XMLs are generated by `tools/make-factory-presets.mjs`, which also knows every control's
range and refuses to write a value outside one. The XMLs are the bank and are committed; the
script is how they were made. **The bank is a placeholder**: thirty patches that show the
engine's range, to be replaced by the author's own.

## The dirty marker

Dirty is a comparison, not a flag: the patch's fingerprint against the fingerprint it had when
it was loaded. So a patch edited and then put back by hand is not dirty, and a load is never
mistaken for an edit.

The fingerprint quantises values to six significant digits, and that is not tidiness - a
parameter stores a NORMALISED value, so writing 4000 Hz into a tree and reading it back can
give 4000.0005. Hash the raw floats and loading a preset lights the dirty dot by itself.


## The roll

One dice, five locks, one undo. A roll moves every UNLOCKED section:

| Section | What it moves |
|---|---|
| FM | index, per-op ratio/level/feedback/wave, operator envelopes, the routing matrix and the carriers |
| VA | level, shape morph, octave, detune, sub, noise, the VA envelope |
| Filter | the global filter; one or two per-op filters with their envelopes |
| Mod | the 32 matrix slots and all the editable shapes |
| FX | two to four modules, their controls, bypass |

What makes it musical rather than random:

- **Ratios come from a musical set.** A uniform draw over 0..16 is inharmonic almost
  everywhere, and 0 stops the operator's phase entirely.
- **The routing is a two-level stack**, not random edges. Random edges produce cycles as often
  as stacks, and a cycle here is a feedback loop with nothing to contain it.
- **Audibility is structural**: the first carrier always gets a real ratio, a real level and a
  sustain that holds. Twenty seeds are checked, not one.
- **A modulation slot moves its destination's base value first**, so the slot has somewhere to
  go - a +0.4 sweep onto a filter sitting wide open is a slot that does nothing.
- **The rack's controls are jittered from the module's own defaults**, and a mix or a level
  moves less than the rest, so a roll cannot land on fully-wet or fully-dry.
- **Locks hold across sections.** A lock means "do not touch this", so the Mod section will not
  place a slot on a parameter whose own section is locked.

The roll is seeded: the same seed and the same locks produce the same patch. Undo is one level
and puts back the whole session position - the patch, the selected preset and the dirty state -
because a hand-edited patch is still hand-edited after an undo.

## The host's programs

`getNumPrograms` / `getProgramName` / `setCurrentProgram` are the same bank, so a DAW and the
browser cannot disagree. An index that does not exist changes nothing.

## The patch bar

`Source/PatchBar.{h,cpp}`, in the header row beside the plugin's name: the browser, `<` `>`,
INIT, SAVE, DEL, the roll with its five locks, UNDO, the patch's name and a dirty dot.

It polls rather than listening. The dirty marker is a fingerprint of the whole patch, and the
parameters it watches are written by the host, by automation and by the editor's own controls -
so a four-hertz poll is both cheaper and more honest than trying to catch every route a change
can arrive by.

## Verification

`MiXXynthPatchAudit` is the gate. It proves, in its own words: the bank arrived, every parameter
a preset names exists, every value is in range, every choice lands on an index, every factory
preset can make a sound, a load is deterministic, a parameter a preset omits comes back at its
default, a saved patch reloads to exactly what was saved, a factory preset cannot be saved over
or deleted, the host sees one program per preset, a roll is reproducible from its seed, a lock
holds, twenty rolls are all audible, a module a roll adds has its controls set, and an undo puts
the patch back exactly.

The name in the bar is the preset's, or `Init` when the patch is the init patch, or
`(unsaved)` when it is neither - a patch the host restored, or one whose preset was deleted.
